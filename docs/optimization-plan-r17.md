# 墨流网文生成质量优化方案 (r17)

**创建日期**: 2026-10-01  
**目标**: 解决用户反馈的"没吸引力"和"正文质量不佳"问题

## 一、问题诊断

### 1.1 当前系统状态
- **验收状态**: NOT READY (r7-r16 连续未达标)
- **S1 致命缺陷**: 11 个 (r16)
  - 人物状态回滚: state.fate
  - 官职头衔漂移: state.title (1个S1 + 9个S2)
  - 章内算术矛盾: number.arithmetic (4个S1)
  - 时序矛盾: time.sequence (3个S1)
  - 章界断裂/主线结构断裂
- **升级信号**: 
  - `persistent-class`: 主线结构断裂连续多轮修不好
  - `shape-shift`: 60% S1 是新类型,问题形态在漂移

### 1.2 "没吸引力"的根因
当前系统主攻 **L6 连续性层**(人物状态、时间线、事实一致性),但用户感受到的"吸引力"来自更上层:

**缺失的核心层级**:
- **L1 开篇层**: 黄金三章的钩子设计
- **L2 节奏层**: 爽点密度与压抑-释放节奏
- **L3 钩子层**: 短线悬念的提出-强化-兑现排期
- **L4 爽点层**: 章事件密度检测(冲突数 + 状态变化数)

### 1.3 "正文质量不佳"的具体表现
1. **AI 腔调**: paragraphLengthCV 0.30 vs 市场基准 0.36-0.40
2. **段落过长**: 中位 72 字 vs 市场中位 36-40 字
3. **叙述段过重**: 对话占比不足
4. **章内重复验算**: 出现"3人×5两=12两"的自相矛盾
5. **节奏拖沓**: 字数控制死板,不区分情节密度

#### P0.3 动态字数目标 (根据节点密度)
**问题**: 当前所有章节固定 3000 字,不区分:
- 动作密集章(打斗/追逐): 需要 3500-4000 字展开细节
- 对话密集章(谈判/审讯): 2500-3000 字即可完整
- 过渡章(赶路/回忆): 2000-2500 字避免注水

**方案**:
```typescript
// 新增函数: 根据章节节点密度计算目标字数
function calculateDynamicWordTarget(chapter: Chapter): number {
  const nodes = chapter.structureNodes;
  if (!nodes) return 3000; // 默认值
  
  // 统计节点数量
  const cpnCount = nodes.CPNs?.length ?? 0;
  const mustCoverCount = nodes.mustCover?.length ?? 0;
  const totalNodes = 1 + cpnCount + 1; // CBN + CPNs + CEN
  const totalBeats = totalNodes + mustCoverCount;
  
  // 动态计算: 基准 2000 + 每节点 400-600 字
  // 2 节点(CBN+CEN): 2000 + 2×400 = 2800
  // 3 节点: 2000 + 3×500 = 3500  
  // 4 节点: 2000 + 4×500 = 4000
  // 5+ 节点: 封顶 4500
  const baseWords = 2000;
  const wordsPerBeat = 500;
  const calculated = baseWords + totalBeats * wordsPerBeat;
  
  // 限制范围: 2500-4500
  return Math.max(2500, Math.min(4500, calculated));
}
```

**注入点**:
- `ChapterWritingPipeline.execute()`: 替换固定 `targetWordCount`
- `useBatchWriter.ts`: 替换 `options.wordsPerChapter`

**预期效果**:
- 减少过渡章注水(当前 3000 字强制导致重复开场)
- 动作章有足够篇幅展开细节
- 整体更符合内容节奏

`- 【段落长度硬要求】:

**4.2 后处理拆分** (兜底):
```typescript
// 新增函数: 智能拆分超长段落
function splitLongParagraphs(paragraphs: string[]): string[] {
  return paragraphs.flatMap(p => {
    const length = countWords(p);
    if (length <= 80) return [p];
    
    // 超过 80 字: 按句号、问号、感叹号拆分
    const sentences = p.split(/([。?!])/u);
    const result: string[] = [];
    let current = '';
    
    for (let i = 0; i < sentences.length; i += 2) {
      const sentence = sentences[i] + (sentences[i+1] || '');
      if (countWords(current + sentence) > 60 && current) {
        result.push(current.trim());
        current = sentence;
      } else {
        current += sentence;
      }
    }
    if (current) result.push(current.trim());
    return result.filter(Boolean);
  });
}
```

**注入点**: `sanitizeSceneDraftParagraphs()` 之后

### 阶段 P1: 爽点与钩子机制 (下一轮)

#### P1.1 章事件密度检测
**目标**: 每章至少 2 个"状态变化"或"冲突事件"

**实现**:
```typescript
interface ChapterEventDensity {
  conflicts: number;        // 冲突数
  stateChanges: number;     // 状态变化数
  emotionalBeats: number;   // 情绪转折数
  total: number;
}

// 从 ChapterMemory 提取
function calculateEventDensity(memory: ChapterMemory): ChapterEventDensity {
  return {
    conflicts: memory.keyEvents.filter(e => 
      e.includes('冲突') || e.includes('对峙') || e.includes('争执')
    ).length,
    stateChanges: memory.characterStateChanges.length,
    emotionalBeats: memory.emotionalTone ? 1 : 0,
    total: memory.keyEvents.length
  };
}
```

**门禁**: total < 2 时触发重写,提示"增加冲突或状态变化"
