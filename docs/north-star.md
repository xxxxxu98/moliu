# 墨流项目终极目标 (North Star)

> **本文件是项目一切开发工作的最高目标声明。** 所有功能、重构、修复都应能回答一个问题：
> 「这个改动推进了哪一层质量目标？」——回答不了的工作降优先级或不做。
> 编码层面的具体规范见 [`development-guidelines.md`](./development-guidelines.md)。

---

## 一、使命（一句话）

**任选题材，全自动生成可投稿主流小说平台的网文：人工零干预，确定性预检全绿，逐章书审无 S1/S2，读者评分 ≥ 80，前三章盲测能骗过老书编，且能稳定跑到完本。**

网文本质是**情绪产品**：读者付费的不是文笔，而是「期待感 → 压抑 → 释放」的循环体验。
因此生产可用的标准不是「写得好」，而是两层：

1. **硬门槛全过**（确定性、可机检）：平台合规红线、原创性、字数结构、能完本不烂尾——做不到直接拒稿；
2. **留存线达标**（情绪层、概率性）：开篇留存、追读率——靠爽点密度、钩子链与期待感管理支撑。

## 二、工程化铁律

每个质量维度都必须转化为软件中可执行的闭环，缺任何一环都只是愿望，不是功能：

```
生成时的结构约束（提示词协议 / 大纲结构化）
  → 生成后的确定性检测（lint / 统计指标 / 预检脚本）
    → AI 审读（逐章书审 / 结构化 Findings 分级）
      → 修复回路（归因分诊 → 代码修复 → 回归验证）
        → 真实验收（矩阵冒烟 / 大循环 / 读者 agent 评分）
```

**禁止**把质量目标停留在「提示词里写一句要求」——没有检测与修复回路的质量要求等于没有要求。

## 三、八层质量目标

按对成书生死的影响排序。每层给出「读者标准」与「软件必须具备的功能」。

### L1 开篇层（黄金三章，决定生死）

- **读者标准**：切入点直接进冲突，无背景说明书式开场；主角目标与困境立得住；前三章内核心爽点至少兑现一次。编辑看稿基本只看前三章。
- **软件功能**：大纲生成强制「首章冲突 + 首爽点位置」结构协议；前三章专项审读；标题/简介/封面点击转化优化。

### L2 节奏层（不拖沓的真正含义）

- **读者标准**：每章有完整微循环（目标 → 阻碍 → 行动 → 结果）且章内闭环、章末开新口；低信息密度段落（环境、回忆、过渡）被压缩。
- **软件功能**：「章事件密度」检测（每章 ≥1 个冲突 + ≥1 个状态变化）；段落节奏指标（已有 paragraphLengthCV 管句式，需补剧情推进维度）。

### L3 钩子与悬念层（追读引擎）

- **读者标准**：章末有钩子留口；读者随时知道「接下来有好事发生或坏事将至」（期待感）。
- **软件功能**：钩子链预检（已有）；悬念账本——悬念的提出 → 强化 → 兑现排期管理（比伏笔更频繁、更短线的账本）。

### L4 爽点层（网文内核）

- **读者标准**：打脸/逆袭/升级等爽点的压抑要足够、释放要及时。常见死法：压抑冗长（弃书）或爽点空兑现（嘴赢无代价）。
- **软件功能**：大纲节点标注爽点类型与兑现章；检测「连续 N 章无爽点兑现」「爽点兑现前铺垫不足」。

### L5 人物层（代入感的锚）

- **读者标准**：人设前后一致；对话有区分度（不能人人一个腔调）；主角动机连续不漂移。
- **软件功能**：人物状态连续性（已有：死亡仲裁、实体消歧、状态幻觉扫描）；补对话区分度检测；OOC 预警。

### L6 连续性层（AI 长篇最大死穴）

- **读者标准**：时间线、人物位置、物品、伤势、势力关系跨章一致；前后无矛盾。
- **软件功能**：agent 检索回路 + 事实提取 + 逐章书审（已有，主力投入区）；跨章状态账本。

### L7 文笔层（入场券，做到不出戏即可）

- **读者标准**：无 AI 味（模板句、排比腔、词频复读）；段落长短有变化；画面感（五感细节而非抽象概述）；对话推进剧情。网文对文笔容忍度高，不必追求文学性。
- **软件功能**：AI 词频检测、段落 CV、跨章复读扫描（已有）；去 AI 味修复回路。

### L8 市场合规层（投稿硬门槛）

- **读者标准**：题材在有读者盘的赛道且有微创新；标题简介封面决定点击；无敏感红线；无抄袭撞文；能完本。
- **软件功能**：扫榜选品（已有）；敏感词预检；原创性/撞文检测（**空白**）；完本收束质量验收（烂尾 = 白写）。

## 四、生产可用验收门 (Production Gate)

「生产可用」的唯一验收定义，任何宣称可上线的版本必须全过：

| # | 验收项 | 标准 |
|---|--------|------|
| 1 | 规模 | 任选题材，全自动 100 章，人工零干预 |
| 2 | 确定性预检 | 钩子链 / 引号 / 章界重演 / AI 词频 / 段落 CV 等全绿 |
| 3 | 逐章书审 | AI 审读无 S1（致命）/ S2（严重）Findings |
| 4 | 读者评分 | 读者 agent 打分 ≥ 80 |
| 5 | 盲测 | 前三章人工盲测能骗过老书编 |
| 6 | 完本能力 | 稳定跑到目标字数且结局收束质量达标 |

其中 1–4 由 `storyflow-release-loop` 大循环承载；5、6 是当前缺口，补齐前不算生产可用。

## 五、当前主攻缺口（按优先级，2026-08-29 冻结）

> 此清单会随落地更新；更新时保留日期戳。

1. **爽点密度与压抑-释放节奏**：从「读者 agent 打分」虚指标变成确定性指标 + 排期管理（L4）。
2. **期待感/悬念账本**：短线悬念的提出-强化-兑现排期，补钩子链之上的上层管理（L3）。
3. **章事件密度检测**：每章「冲突数 + 状态变化数」的确定性统计（L2）。
4. **对话区分度检测**：多角色对话的语气/句式区分度指标（L5）。
5. **外部原创性检测**：与既有 published 作品的撞文/复读检测（L8）。
6. **完本收束验收**：结局伏笔回收率、主线收束质量的专项书审（L8）。
7. **标题/简介转化优化**：多候选生成 + A/B 评分（L1）。
