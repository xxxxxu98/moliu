## 一、产品概述

### 1.1 产品定位

墨流是一款面向网文作者的**超长篇小说AI协作写作工具**，支持对接多厂商AI模型，通过创新的**分层记忆架构**解决大模型在长文本创作中的遗忘与幻觉问题，实现百万字级小说的连贯创作。

### 1.2 核心痛点

当前AI写作工具在超过10万字后普遍出现：

- **角色遗忘**：主角名字、性格、外貌前后不一致
- **设定崩坏**：世界观规则、势力关系、时间线混乱
- **情节断层**：伏笔丢失、支线失控、节奏失衡
- **风格漂移**：文笔、语气、叙事视角不统一

根据2026年行业测试，即使Claude 200K上下文窗口（约15万字）或Gemini 1M窗口，仍存在"lost-in-the-middle"效应——模型对长文本中间部分的信息提取可靠性显著下降。

## 二、技术架构与核心解决方案

### 2.1 三层记忆系统 (Triple-Memory Architecture)

针对百万字级创作，我们采用**外部记忆库 + 滑动上下文 + 模型原生窗口**的三层架构：

```
┌─────────────────────────────────────────────────────────────┐
│  Layer 3: 全局记忆库 (Global Memory)                        │
│  • 向量数据库 + 结构化知识图谱                                │
│  • 存储：角色档案、世界观设定、情节大纲、伏笔追踪              │
│  • 容量：无上限（仅受存储限制）                               │
├─────────────────────────────────────────────────────────────┤
│  Layer 2: 工作上下文 (Working Context)                        │
│  • 当前章节 + 前3章 + 相关记忆片段                            │
│  • 动态检索注入，约5K-15K tokens                              │
├─────────────────────────────────────────────────────────────┤
│  Layer 1: 模型原生窗口 (Native Window)                        │
│  • 当前输入 + 即时输出                                        │
│  • 依赖接入模型的实际能力（32K-1M tokens）                    │
└─────────────────────────────────────────────────────────────┘
```

**技术原理**：

- **RAG检索增强**：将百万字小说分块向量化，创作时实时检索相关片段注入上下文
- **结构化记忆**：关键设定（角色、地点、规则）以结构化形式存储，而非纯文本
- **智能摘要**：对远距离章节自动生成摘要，替代全文加载

### 2.2 长文本防遗忘机制


| 问题类型     | 解决方案    | 技术实现                        |
| -------- | ------- | --------------------------- |
| **角色遗忘** | 角色档案系统  | 每个角色维护独立向量空间，写作时自动检索相关角色关系  |
| **设定崩坏** | 世界观知识图谱 | 实体-关系-规则三元组存储，AI生成前强制校验     |
| **情节断层** | 伏笔追踪器   | 关键事件标记状态（未揭示/已揭示/回收），自动提醒回收 |
| **风格漂移** | 文风指纹    | 提取作者/作品的语言特征向量，作为生成约束条件     |


### 2.3 幻觉抑制策略

1. **事实校验层**：生成内容先经过与记忆库的冲突检测，发现矛盾时触发修正
2. **引用溯源**：所有设定调用必须关联到原始出处章节
3. **置信度评分**：对AI生成的事实性陈述标注置信度，低置信内容提示人工确认
4. **多模型交叉验证**：关键设定变更时，可配置多厂商模型投票确认

### 3.2 智能创作工作台

#### 3.2.1 大纲架构师

- **故事蓝图**：三幕式/英雄之旅/自定义结构模板
- **章节规划**：自动生成章纲，标注节奏曲线（起承转合）
- **人物弧光**：角色成长轨迹可视化，标记转变节点
- **多线并行**：主线/支线/暗线时间轴对照编辑

#### 3.2.2 章节写作引擎

- **智能续写**：基于前文+记忆库生成下一段落
- **风格迁移**：学习作者已有章节的文笔特征
- **对话优化**：检测"他说/她说"过度使用，建议动作替代
- **节奏控制**：实时统计段落长度、场景切换频率，提示节奏疲劳

#### 3.2.3 一致性守护者（核心功能）

- **角色一致性雷达**：
  - 自动提取角色当前章节的行为/语言特征
  - 与角色档案比对，标记OOC（Out of Character）风险
  - 示例：检测到"冷酷杀手突然温柔体贴"，触发预警
- **设定冻结区**：
  - 作者可锁定关键设定（如"主角不能死"、"境界体系不变"）
  - AI生成时强制遵守，尝试突破时拦截并提示
- **伏笔回收提醒**：
  - 自动识别埋下的伏笔（神秘物品、未解对话、异常事件）
  - 在合适章节提示回收，避免烂尾
  - 统计伏笔回收率，生成"挖坑-填坑"健康度报告

### 3.3 百万字级项目管理


| 功能       | 说明                         |
| -------- | -------------------------- |
| **分卷管理** | 支持按卷/部/篇组织，每卷独立记忆空间+全局共享设定 |
| **增量存储** | 章节级版本控制，支持回溯到任意历史版本        |
| **全文检索** | 基于向量的语义检索（"找主角第一次使用能力的场景"） |
| **关系图谱** | 人物关系、势力关系、事件因果的可视化图谱       |
| **字数统计** | 实时字数/预估完本字数/更新频率分析         |


### 3.4 辅助工具集

- **起名大师**：基于世界观语言风格生成人名、地名、功法名
- **战斗推演**：输入双方实力参数，AI模拟战斗过程并生成描写
- **情感曲线**：分析全文情感走向，标记高潮/低谷位置
- **敏感词预检**：对接各平台审核规则，提前标记风险内容

## 四、长文本技术实现详解

### 4.1 分块与索引策略

```python
# 伪代码示例：智能分块策略
class ChapterChunker:
    def chunk(self, chapter_text):
        # 1. 按场景分割（以场景切换为界）
        scenes = split_by_scene(chapter_text)
        
        # 2. 每个场景提取：
        #    - 摘要向量（发生了什么）
        #    - 实体向量（谁参与了）
        #    - 情感向量（情绪基调）
        for scene in scenes:
            yield {
                'text': scene,
                'summary_embedding': embed(summary(scene)),
                'entity_embedding': embed(entities(scene)),
                'emotion_embedding': embed(emotion(scene)),
                'metadata': {
                    'characters_present': extract_characters(scene),
                    'location': extract_location(scene),
                    'plot_points': extract_events(scene),
                    'chapter_id': chapter.id
                }
            }
```

### 4.2 上下文组装算法

当续写第N章时，系统按以下优先级组装上下文：

1. **必须包含**：第N-1章全文（直接衔接）
2. **高度相关**：通过RAG检索与当前章节主题相似的3-5个历史章节片段
3. **结构化注入**：角色档案（当前出场角色）+ 当前地点设定 + 时间线状态
4. **作者指令**：本章写作要求、风格提示、必须包含的元素
5. **全局约束**：世界观规则、已锁定设定、未回收伏笔清单

### 4.3 记忆压缩机制

对超过50章的历史内容，自动执行**分层摘要**：

- **L1摘要**：每5章生成一段情节摘要
- **L2摘要**：每20章基于L1摘要生成阶段总结
- **L3摘要**：全书梗概（用于极远距离检索）

检索时优先匹配L1，未命中则上溯L2/L3。

### 5.2 关键交互流程

**续写流程**：

1. 作者点击"AI续写"或设定自动续写触发条件（如写完一段后）
2. 系统后台执行：
  - 检索相关记忆 → 组装上下文 → 调用AI模型
  - 生成内容先经过一致性校验层
  - 标记潜在风险（如新角色与旧角色重名）
3. 编辑器以差异形式展示AI建议，作者可：
  - 接受 / 拒绝 / 部分采纳 / 要求重写

## 六、非功能性需求

### 6.1 性能指标


| 指标        | 目标值                        |
| --------- | -------------------------- |
| 百万字项目加载时间 | < 3秒                       |
| AI续写响应时间  | < 15秒（标准模型）/ < 30秒（长上下文模型） |
| 一致性检查延迟   | < 2秒（本地缓存）/ < 5秒（全量检索）     |
| 同时管理项目数   | 无上限（基于本地存储）                |


### 6.2 数据安全

- 所有API Key本地加密存储（AES-256），不上传云端
- 作品内容默认本地存储，可选加密同步至私有云
- 支持完全离线模式（对接本地模型）

### 6.3 兼容性

- **桌面端**：Windows / macOS / Linux
- **移动端**：iPad / Android平板（辅助审阅）
- **文件格式**：导入导出 .docx / .epub / .txt / .md
