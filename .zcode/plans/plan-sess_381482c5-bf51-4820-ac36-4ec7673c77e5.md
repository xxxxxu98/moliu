# 修复 P0-1（mustCover 卷目标污染死锁）+ P0-2（偏短不补字、重写越写越短）

## 根因（已定位，本次 smoke 真实验证）

**P0-1**：`enhanced-context-agent.ts:100-105` 的 `enrichMustCoverWithVolumeSellingPoints` 把卷级 `volume.objective`（"完成清河县亏空清账、清丈田亩、重定税则、汰换吏员"）当作"卖点候选"追加进单章 mustCover。`isLikelyVolumeScopedObjective`（:720）的 5 个正则只认"打败/治理成…模范"等标志词，覆盖不到本案例；`splitPlotClauses`（chapterBlueprintNormalize.ts:419）按 `，,；;。！？!?` 拆、不含`、`，导致整条 22 字卷目标蒙混进入 → 单章 mustCover = 2(大纲)+1(卷objective)+1(CEN)=4 → 门禁要求第2章兑现全卷目标 → 连环重写熔断 → 整批失败。

**P0-2（三处独立缺陷叠加）**：①`SceneDraftEngine.ts:217-224` 重写 prompt 用"必须整章重写"且无"禁止压缩"指令，模型倾向精炼重生成（2372→2484→…→2189）；②`LongFormWritingEngine.padDraftsToTarget`（:397-402）偏短分支直接 return 不补字，补字在长篇路径完全失效；③`:345-355` 重写用尽后无条件移除字数 blocking → 第1章 2534<2400 仍通过。

## 修复方案（按推荐项）

### 改动 1 — P0-1：彻底切断卷 objective → 单章 mustCover
**文件**：`src/renderer/src/services/ai/agents/enhanced-context-agent.ts`
- 修改 `volumePlanSellingPointCandidates`（:663-670）：**移除 `plan.objective`**，只保留 `plan.coreConflict` 和 `plan.payoffForeshadows`。objective 天然是跨卷/跨章承诺，本就不该当单章硬约束（与文件 :654-662、:696-708 已有注释的设计意图一致——那里本就在防御 objective 注入死锁）。
- 更新 :663 上方注释，说明 objective 已整体排除（天然跨章，注入即死锁）。
- 保留 `isLikelyVolumeScopedObjective` / `enrichMustCoverWithVolumeSellingPoints` 的过滤链不动（对 coreConflict/payoffForeshadows 仍需防御兜底）。

**测试**：`src/renderer/src/services/ai/agents/__tests__/enhanced-context-agent.test.ts`
- 更新 `volumePlanSellingPointCandidates` 用例（:95-114）：objective 不再出现在返回值。
- 更新 `enrichMustCoverWithVolumeSellingPoints` 的"卷级 objective 不注入"用例（:219-228）：断言objective 不注入（行为不变，只是路径从"正则过滤"变成"压根不进候选"）。
- 新增回归用例：针对"完成清账、清丈田产、重定税则、卑换吏员"这种纯`、`分隔多动作并列卷目标，断言不注入单章 mustCover。

### 改动 2 — P0-2①：重写 prompt 禁止压缩
**文件**：`src/renderer/src/services/story-runtime/SceneDraftEngine.ts`
- 修改 `revisionRules`（:217-224）：
  - 把序言"必须整章重写并修复下列问题"改为"必须修复下列问题；**原稿已写到的场面/对话/感官细节必须保留，只能在其上叠加新内容兑现未履约节点，禁止把既有情节压缩成梗概或换更紧凑措辞重写**"。
  - 当 revisionHints 含字数类（含"字数严重不足"）时，额外追加一条："- 【字数】本次必须在原稿基础上扩写补足字数，禁止以重写为名压缩篇幅"。
- 这是纯 prompt 文案改动，无逻辑改动，无单测（prompt 文案不测断言）。

### 改动 3 — P0-2②：长篇路径接入 append-only 补字
**文件**：`src/renderer/src/services/story-runtime/LongFormWritingEngine.ts`
- 新增 private 方法 `padDraftsIfUnderTarget`（与 `trimDraftsIfOverTarget` 对称），在 `padDraftsToTarget`（:397-402）偏短分支调用：
  - 复用 `this.dependencies.ai.generate<string[]>` 范式（同 `trimDraftsIfOverTarget` :445-461）：purpose=`'scene-draft'`、schemaName=`'SupplementParagraphs'`、system 要求只输出 `{"paragraphs":[...]}` JSON。
  - prompt 复用 `supplement.ts` 的 `buildSupplementPrompt`（outputFormat=`'json'`，注释明确是为本路径准备的）。
  - 字数策略：用 `checkWordCountBounds` 判定，shortfall 一次补足（目标 maxWords）；最多补 1-2 轮（单轮失败保留原稿，不抛错，与 trim 对称）。
  - 补出的段落经 `sanitizeSceneDraftParagraphs` 清洗后追加到 `drafts[0].paragraphs`。
- 更新 `padDraftsToTarget`（:380-382、:397-402）注释：偏短现在走 append-only 补字（与超长走压缩对称），移除"补字会割裂文气故统一移除"的旧注释。
- 新增 import：`buildSupplementPrompt`、`sanitizeSceneDraftParagraphs`、`SceneDraft`（如未导入）。

**测试**：`src/renderer/src/services/story-runtime/__tests__/LongFormWritingEngine.test.ts`（若存在）或就近测试
- 新增用例：mock ai.generate，给定偏短 drafts（如 1500 字/目标 3000），断言补字后被调用、drafts.paragraphs 被追加、字数提升。
- 现有超长压缩用例不受影响。

### 改动 4 — 字数放行保持不变（按推荐）
- `LongFormWritingEngine.ts:345-355` 重写用尽后移除字数 blocking 的逻辑**保持不动**。
- 理由：改动 3 接入补字后，偏短章节会在 pad 阶段被补到位，此移除逻辑自然不再触发；保留它作为"补字也失败时的兜底"，避免无谓拒收。改动最小，不引入新风险。

## 风险与回滚
- 改动 1（移除 objective 候选）副作用：卷级卖点传导变弱（单章 mustCover 少一条卷目标提示）。但本就因死锁而无法正常工作，移除是净改善。
- 改动 3（接入补字）新增一次 AI 请求/章（仅偏短时），增加耗时与 token，但换取字数达标。
- 全部改动集中在 3 个文件 + 对应测试，可独立回滚。
