# 批量续写 schema 校验崩溃修复计划

## 根因总结

两个独立 bug，都因 AI 模型输出偏离 zod schema 导致整章判为「持久错误」被跳过：

| Bug | 现象 | 根因 |
|-----|------|------|
| 1 | 事实提取 `expected object, received array` | `coerceExtractedFacts`(schemas.ts:129) 对裸数组无能为力——数组 `typeof==='object'` 绕过早返回，但 `z.object` 仍拒绝数组 |
| 2 | `inventory["晶核"].unit/note` `expected number, received string` | 模型把物品写成 `{晶核:{unit:"颗",note:"灵力结晶"}}` 挂到 inventory；`FactCanonicalizer.ts:196` 的正则 `^inventory\.([^.]+)\.(.+)$` 只匹配三段路径，对两段 `inventory.<owner>` set 整个对象、或非标准路径均漏网；schema 无兜底 → 校验崩 |

共用辅助前提：已确认 inventory 契约为 `Record<ownerId, Record<itemId, number>>`（types/story-runtime.ts:63），所有消费者（ContinuityValidator/SceneBeatPlanner/FactCanonicalizer）都按数字叶子取值，**不改变契约**，只加容错。

---

## 修复方案（4 层防御 + 测试）

### 层 1 — 事实提取裸数组容错【对应 Bug 1】
**文件：** `src\renderer\src\services\story-runtime\schemas.ts`（`coerceExtractedFacts`，第 129-147 行）

在函数最开头增加数组分支：模型返回裸数组时，按元素特征分类包装为 `{events, deltas, evidence}` 对象：
- 元素是对象且含 `summary` 或 `id` → 归入 `events`
- 元素是对象且含 `operation`/`path` → 归入 `deltas`
- 其余（含字符串）→ 归入 `evidence`（字符串）或忽略
- 打印 warn（与现有兜底一致风格）

### 层 2 — Prompt 根因强化【对应 Bug 2 根因 + 强化 Bug 1】
**文件：** `src\renderer\src\services\story-runtime\FactExtractor.ts`（system prompt，第 56-66 行）

在现有契约列表追加：
- `5) deltas.path 必须形如 inventory.<角色实体id>.<物品名>，value 必须是数字（数量），禁止写 {unit,note,quantity} 等对象`
- `6) 顶层必须输出一个 JSON 对象（{...}），禁止输出裸数组`
- 把第 65 行示例的 `"path":"string","value":{}` 改为更具体的示例：含一条 `inventory.char-1.银两` value=数字 的 delta，去掉误导性的 `value:{}`

### 层 3 — FactCanonicalizer 写入防御强化【对应 Bug 2 写入路径】
**文件：** `src\renderer\src\services\story-runtime\FactCanonicalizer.ts`（第 194-221 行 deltas map）

扩展为更通用的 inventory 归一化，新增共享辅助函数：

**新增辅助（放 schemas.ts 与 `coerceIdString` 同区，便于层 4 复用）：**
```
extractInventoryNumeric(leaf: unknown): number | undefined
```
- number/有限 → 原值
- 纯数字字符串（复用现有 `/^[+-]?[0-9]+(\.[0-9]+)?$/u` 规则）→ Number
- 对象 → 按优先级查 `[quantity, count, amount, num, value, 数量, 数, 个数, 数目]`，取首个可转有限数字的字段；都无则返回 undefined
- 其他（boolean/null/数组/纯描述对象）→ undefined

**Canonicalizer 改造：**
- 保留现有三段 `inventory.<owner>.<item>` 匹配，但 value 改用 `extractInventoryNumeric`（替代当前直接丢弃对象的逻辑，救回 `{quantity:5,...}`）
- **新增两段 `inventory.<owner>` 匹配**（value 为对象）：遍历 value 的每个 itemKey，对每个叶子调 `extractInventoryNumeric`，数字有效则展开为 `inventory.<owner>.<itemKey>` set delta，无效则丢弃该 item
- owner 仍走 `resolveParticipant` 归一化
- 非 inventory 路径原样透传（不误伤）

### 层 4 — storyStateSchema inventory 兜底 preprocess【对应 Bug 2 校验路径 + 历史损坏数据】
**文件：** `src\renderer\src\services\story-runtime\schemas.ts`（第 98 行 inventory 字段 + 第 94-103 行 schema）

把 `inventory: z.record(z.string(), z.record(z.string(), z.number()))` 包一层 preprocess：
```
inventory: z.preprocess(coerceInventoryRecord, z.record(z.string(), z.record(z.string(), z.number())))
```
`coerceInventoryRecord(value)` 行为：
- 非 object/array → 原样返回（让 zod 报错）
- 遍历每个 owner（key 非对象 → 丢弃整个 owner）
- 遍历 owner 下每个 item，叶子调 `extractInventoryNumeric`；返回 undefined 则删除该 item key
- 整个 owner 变空 → 删除该 owner key
- 有丢弃时 warn（与 coerceExtractedFacts 风格一致）

效果：写入路径漏网的对象/字符串 value、或已落盘的损坏 snapshot，loadState 时不再崩，项目可恢复。

## 测试

### `__tests__\extractedFactsSchema.test.ts`（扩展）
- 裸数组且元素像 event → 包装为 `{events:[...], deltas:[], evidence:[]}` 通过
- 裸数组元素是 delta（含 operation/path）→ 归入 deltas
- 裸数组元素是字符串 → 归入 evidence

### `__tests__\FactCanonicalizer.test.ts`（扩展，第 99 行附近）
- 新增：`inventory.<owner>` 两段 set 对象 `{晶核:{unit:"颗",note:"灵力结晶"}, 银两:{quantity:5}}` → 展开为 `inventory.<owner>.银两`=5（数字字段提取），`晶核` 因无数字字段被丢弃
- 新增：三段 `inventory.<owner>.物品` value 为对象 `{quantity:3,unit:"颗"}` → 提取为 3（替代当前"对象直接丢弃"）
- 现有「Bug 9」「严格数字校验」用例保持通过（对象 `{描述:'一把剑'}` 仍丢弃，因为无数字字段）

### storyState schema inventory 容错（新增测试块）
- inventory 叶子为数字字符串 → 转 number
- inventory 叶子为 `{quantity:2}` → 提取 2
- inventory 叶子为 `{unit:"颗",note:"x"}` → 丢弃该 item
- 整个 owner 无有效 item → owner 被删除
- 纯数字 inventory 不受影响（回归）

## 不改动项（明确边界）
- `types/story-runtime.ts:63` inventory 类型 `Record<string, Record<string, number>>` 保持不变
- ContinuityValidator / SceneBeatPlanner 的 inventory 数值消费逻辑不动（叶子仍为 number）
- stateOverlay.applyDelta 不动（它只按 path 写值，源头规范化后即正确）
- 不引入运行时 JSON Schema 推送到模型（超出本次范围）
